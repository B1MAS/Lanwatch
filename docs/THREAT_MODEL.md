# Модель угроз LANwatch

## Область рассмотрения

Эта модель описывает риски локального запуска LANwatch для домашней или небольшой корпоративной сети. Она охватывает получение данных от роутера, локальное хранение, веб-панель, экспорт и опциональные уведомления.

Модель не предполагает, что LANwatch защищает уже скомпрометированный компьютер или заменяет сегментацию сети, SIEM, IDS/IPS, EDR и антивирус.

## Защищаемые данные

- учётные данные и временные токены доступа к роутеру;
- IP- и MAC-адреса, имена и состояние устройств;
- DNS, сведения о WAN, прошивке и перезагрузках;
- доверенная база устройств и DNS;
- история событий и снимков сети;
- целостность результатов аудита и предупреждений.

## Предположения

- LANwatch запускается на доверенном компьютере под отдельной пользовательской учётной записью;
- пользователь получает программу из проверенного репозитория и просматривает изменения перед обновлением;
- роутер доступен по локальному адресу, а его административный пароль не передаётся через командную строку;
- для OpenWrt используется отдельная учётная запись с минимальным read-only ACL;
- пользователь проверяет экспортируемые файлы перед публикацией или отправкой третьим лицам.

## Границы доверия

1. **Роутер → LANwatch.** Ответы API являются недоверенным вводом.
2. **LANwatch → локальное хранилище.** Снимки и события могут содержать идентификаторы сети.
3. **LANwatch → браузер.** Веб-интерфейс должен оставаться доступным только на loopback.
4. **LANwatch → внешние сервисы.** Webhook, Telegram и загрузка OUI-базы создают исходящие соединения только по явному запросу.
5. **Пользователь → GitHub/мессенджер.** Диагностика и экспорт могут быть опубликованы только после ручной проверки.

## Основные угрозы и меры защиты

| Угроза | Возможные последствия | Реализованные меры |
| --- | --- | --- |
| Подмена адреса роутера или перенаправление запроса | Передача учётных данных постороннему узлу | Разрешены только локальные IP-адреса; HTTP-перенаправления запрещены |
| Перехват пароля OpenWrt по HTTP | Компрометация учётной записи роутера | По умолчанию требуется HTTPS; HTTP включается только явным флагом для изолированной доверенной LAN |
| Избыточные права учётной записи | Изменение конфигурации при компрометации клиента | Рекомендуется отдельный read-only ACL; OpenWrt-адаптер использует allowlist методов чтения |
| Сохранение секрета на диске | Кража пароля или токена из файлов состояния | Пароль и токен роутера не записываются на диск; интерактивный ввод скрыт |
| Утечка топологии через диагностику | Раскрытие IP, MAC, имён устройств и локальных путей | `probe` формирует минимальный отчёт без этих данных и ничего не отправляет автоматически |
| Публикация полного экспорта событий | Раскрытие сетевых идентификаторов | Документация предупреждает, что JSONL/syslog/CEF необходимо проверить перед передачей |
| Удалённый доступ к панели | Просмотр локальных событий другим устройством | Привязка только к `127.0.0.1`; запуск на `0.0.0.0` отклоняется |
| CSRF или подмена `Host` | Выполнение нежелательного действия через браузер | Случайный CSRF-токен, строгая проверка `Host`, ограничение размера POST |
| XSS через имя устройства или данные роутера | Выполнение кода в локальном браузере | Экранирование отображаемых данных, CSP и отсутствие сторонних скриптов |
| Неявная отправка данных наружу | Потеря конфиденциальности | Исходящие уведомления выключены по умолчанию и передают минимальный набор полей |
| Ложное чувство защищённости | Пропуск атаки, которую роутер не показывает | Недоступные проверки отмечаются как `UNKNOWN`; ограничения явно описаны |

## Остаточные риски

- Компрометация компьютера пользователя позволяет читать локальные данные и перехватывать вводимые секреты.
- Если роутер предоставляет API только по HTTP, трафик внутри локальной сети не имеет транспортной конфиденциальности.
- Взломанный роутер может возвращать ложные или неполные сведения.
- Локальный ARP-кэш может быть устаревшим или неполным.
- Экспорт событий содержит больше данных, чем минимальный `probe`-отчёт.
- Слишком частый мониторинг и длительное хранение истории могут увеличить нагрузку и размер локальной базы.

## Что LANwatch намеренно не делает

- не меняет настройки роутера;
- не блокирует устройства и соединения;
- не сканирует подсеть и порты;
- не анализирует содержимое всего сетевого трафика;
- не обнаруживает гарантированно вредоносное ПО или все виды атак;
- не открывает веб-панель для других устройств сети;
- не отправляет полные события во внешние сервисы автоматически.

## Сообщение об уязвимости

Не публикуйте рабочий эксплойт, пароль, токен, IP/MAC-адреса или реальные логи сети в открытом Issue. Используйте инструкции из корневого файла [`SECURITY.md`](../SECURITY.md) и перед отправкой удалите чувствительные данные.

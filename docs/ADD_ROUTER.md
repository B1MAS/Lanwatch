# Как помочь проекту и добавить свой роутер

LANwatch использует отдельный адаптер для каждого типа локального API роутера.
Если вашей модели пока нет в [таблице совместимости](COMPATIBILITY.md), создайте
заявку. Для этого не нужно уметь программировать.

## 1. Подготовьте безопасный отчёт

Откройте терминал в папке LANwatch и выполните:

```text
python -m lanwatch probe --router http://192.168.1.1
```

Замените адрес на локальный адрес панели вашего роутера. Например, для многих
роутеров Xiaomi используется `http://192.168.31.1`.

Команда создаст в текущей папке файл `lanwatch-probe.json`. Она не запрашивает
пароль, не авторизуется в панели и не собирает список устройств или полные
ответы API.

Если LANwatch установлен через установщик, можно использовать launcher:

```text
lanwatch probe --router http://192.168.1.1
```

В Windows вместо `lanwatch` может потребоваться путь к `lanwatch.cmd`, который
показал установщик.

## 2. Проверьте файл перед отправкой

Откройте `lanwatch-probe.json` обычным текстовым редактором. В нём не должно
быть:

- паролей, токенов и cookies;
- SSID и пароля Wi-Fi;
- публичного или локального IP роутера;
- MAC/IP-адресов и имён домашних устройств;
- локальных путей и имени пользователя компьютера;
- полных ответов API роутера.

Если вы заметили такие данные, не публикуйте файл и сообщите об этом как об
ошибке без прикрепления самого файла.

## 3. Создайте заявку

Откройте форму **[«Поддержка нового роутера»](https://github.com/B1MAS/lanwatch/issues/new?template=router_support.yml)**
и укажите:

1. производителя и точную модель;
2. версию прошивки;
3. известный тип локального API, если он вам известен;
4. проверенный файл `lanwatch-probe.json`.

Файл можно перетащить в поле заявки. Он не отправляется разработчику
автоматически.

## 4. Если отчёта недостаточно

Безопасный `probe` показывает среду и результат определения известных API, но
не копирует содержимое неизвестного API. Поэтому одного отчёта иногда
недостаточно для создания нового адаптера.

В таком случае обсуждение продолжится в заявке. Для конкретной модели будет
подготовлена отдельная инструкция или ограниченный сборщик с удалением
чувствительных полей. Публикуйте дополнительные данные только после их ручной
проверки.

Не прикладывайте к публичной заявке:

- резервную копию конфигурации роутера;
- полный диагностический архив производителя;
- дамп сетевого трафика;
- экспорт событий LANwatch;
- скриншоты со списком домашних устройств;
- пароль администратора, токены или cookies.

Такие файлы могут содержать секреты даже тогда, когда это не видно по их
названию.

## Хотите добавить адаптер самостоятельно?

1. Создайте отдельную ветку от актуальной `main`.
2. Возьмите за основу [`ADAPTER_TEMPLATE.py`](ADAPTER_TEMPLATE.py).
3. Используйте только необходимые read-only endpoint.
4. Добавьте тесты с полностью синтетическими данными.
5. Обновите [`COMPATIBILITY.md`](COMPATIBILITY.md) и основной README.
6. Выполните тесты:

```text
python -m unittest discover -s tests -v
```

После этого создайте pull request и укажите проверенную модель, прошивку,
поддерживаемые возможности и известные ограничения.
